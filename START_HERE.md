2.  Commit meaningful milestones to Git.

5.  Ask for clarification when a requirement conflicts with the SRS/blueprint.

## Authority

The original developer system blueprint PDF (`executive_ai_workforce_control_room_twenty_crm_separate_control_plane_v2.pdf`, v2.0) remains the authoritative product specification for the Observation Plane, Control Plane, and Twenty connector. These markdown files are the mentoring/workflow layer built on top of it.

The Vendor Distribution Plane (Phase 2 — build signing, licensing, updates) comes from separate architecture diagrams supplied later and is not in the original blueprint PDF. It has been folded into CLAUDE.md/PROJECT_CONTEXT.md/WEEKLY_ROADMAP.md/CHECKLIST.md as an explicit Phase 2, sequenced after the Phase 1 core system.

If a coding decision conflicts with the SRS/blueprint or the diagrams, flag the conflict instead of silently changing the requirement.
